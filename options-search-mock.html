Options search — UX mock

Breadcrumbed, grouped search results rendered inside the existing Options window. Simple settings are editable in place; anything non-primitive links to its real page, with browser-style back/forward tying it together.

1Results — grouped by path

Query light. Groups nest by the option's path. Primitive settings (Option.Checkbox, Option.Slider, Option.ComboBox…) render their real widget inline and are editable here. Non-primitives get a jump link.

5
The results pane scrolls, not the window. The rail already has its own scroller (WrapInScroll(MAX_HEIGHT), OptionsWindow.cs:218); the content column needs the same treatment so the query box — grid row 0 — stays put while you scroll results. Without it the window's own outer ScrollViewer engages and drags the search box and rail off the top with the list.
6
No sticky group headers. Myra has no sticky-positioning support, so a long group scrolls its header away. Mitigated by collapsing: with 34 hits the useful move is collapsing the groups you don't care about, which is why hit counts sit on every header.
7
Scroll offset and collapse set live in the history entry, so leaving for a jump and hitting ◀ puts you back at the same place in the same list — not at the top of a freshly re-run search.

5Narrow window — inlining backs off

Same light query at ~430px. A primitive that no longer fits beside its label is demoted to a jump link. Demotion is one-way: measurement can push a row out of inline, never pull one in, so nothing ever surprises you by appearing inline.

6The one new user setting

Lives in Options itself. Governs how eagerly primitives inline. Never is the full opt-out — every result becomes a crumb plus a link, identical at any window size, which covers very small viewports without any special-casing.

Fraction of the available row width a widget may claim and still inline. If this never feels right in practice, the fallback is to drop measurement entirely and discriminate purely on type — primitive inline, everything else its own page — which is exactly what Never and Aggressive already bracket.

What's decided here

Nested grouping by path, breadcrumbs derived top-down from self-names that already exist, primitives inline / non-primitives own page, measurement as a one-way demotion guard with a user-facing threshold, browser-style back/forward with subtab clicks pushing, rail lit on jump, optional match attribution, no character-level highlight tinting.

Paging for search results is replaced by a scroller on the results pane — which retires the BuildPagedResults / PackIntoPages / MaxMatchSize / ComputeResultsBudget space-budgeting system. PageControl itself stays, since OptionPageGroup still uses it for real option pages.

Not in scope: moving any setting between tabs, renaming any visible label, changing the 500ms search debounce, or retuning the Levenshtein strategy.
